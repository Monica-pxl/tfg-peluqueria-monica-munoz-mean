1. POST /api/login
   ────────────────────────────────────────────────────────────
   📝 Descripción: Autentica un usuario y genera un token JWT

   📥 Body (JSON):
   {
     "email": "usuario@example.com",
     "password": "password123"
   }

   📤 Respuesta exitosa (200):
   {
     "mensaje": "Login exitoso",
     "token": "eyJhbGciOiJIUzI1NiIs...",
     "usuario": {
       "_id": "...",
       "id_usuario": "...",
       "nombre": "María López",
       "email": "maria@example.com",
       "rol": "cliente",
       "estado": "activo",
       "puntos": 70,
       "fecha_alta": "2026-01-15T00:00:00.000Z"
     }
   }

   ❌ Errores:
   - 400: Faltan campos obligatorios
   - 401: Credenciales incorrectas
   - 404: Usuario no encontrado

   🔧 Qué hace internamente:
   - Busca usuario por email
   - Verifica contraseña con bcrypt
   - Genera token JWT válido por 2 horas
   - Devuelve datos del usuario (sin password)

   🎯 Usado en frontend:
   - Página de login (todos los roles)
   - Guarda token en localStorage/sessionStorage
   - Redirige según rol (admin/profesional/cliente)


2. POST /api/registro
   ────────────────────────────────────────────────────────────
   📝 Descripción: Registra un nuevo usuario

   📥 Body (JSON):
   {
     "nombre": "Juan Pérez",
     "email": "juan@example.com",
     "password": "password123",
     "rol": "cliente" // opcional, por defecto "cliente"
   }

   📤 Respuesta exitosa (201):
   {
     "mensaje": "Usuario registrado exitosamente",
     "token": "eyJhbGciOiJIUzI1NiIs...",
     "usuario": {
       "_id": "...",
       "nombre": "Juan Pérez",
       "email": "juan@example.com",
       "rol": "cliente",
       "estado": "activo",
       "puntos": 0,
       "fecha_alta": "2026-02-18T..."
     }
   }

   ❌ Errores:
   - 400: Faltan campos o email ya existe

   🔧 Qué hace internamente:
   - Valida que el email no exista
   - Encripta la contraseña con bcrypt
   - Crea usuario con puntos=0 si es cliente
   - Genera token JWT automáticamente
   - Fecha de alta = fecha actual

   🎯 Usado en frontend:
   - Página de registro público
   - Login automático después del registro

5. DELETE /api/usuarios/:id
   ────────────────────────────────────────────────────────────
   📝 Descripción: Elimina un usuario y gestiona todos sus datos relacionados
                   de forma inteligente según el rol

   📤 Respuesta exitosa (200):
   {
     "mensaje": "Usuario eliminado exitosamente"
   }

   ❌ Errores:
   - 404: Usuario no encontrado
   - 500: Error en el proceso de eliminación

   🔧 QUÉ HACE INTERNAMENTE:

   ═══════════════════════════════════════════════════════════
   SI EL USUARIO ES PROFESIONAL:
   ═══════════════════════════════════════════════════════════

   1️⃣ BUSCAR REGISTRO DE PROFESIONAL
      - Encuentra el profesional asociado al usuario
      - Si no existe, solo elimina el usuario

   2️⃣ ELIMINAR RELACIONES PROFESIONAL-SERVICIO
      - Borra todas las asignaciones de servicios
      - deleteMany({ profesional: id })
      - Log: Cantidad eliminada

   3️⃣ ELIMINAR HORARIOS DEL PROFESIONAL
      - Borra todos los horarios laborales
      - deleteMany({ profesional: id })
      - Log: Cantidad eliminada

   4️⃣ CANCELAR CITAS FUTURAS Y NOTIFICAR CLIENTES
      - Busca citas con estado: 'pendiente' o 'confirmada'
      - Solo las que sean futuras (fecha >= hoy)
      - Para cada cita:

        a) Guardar datos históricos (si no existen):
           • usuarioNombre (del cliente)
           • usuarioEmail (del cliente)
           • profesionalNombre
           • profesionalApellidos
           • servicioNombre
           • centroNombre

        b) Cambiar estado a 'cancelada'

        c) Enviar notificación al CLIENTE:
           Título: "Cita cancelada por el centro"
           Mensaje: "Tu cita de [Servicio] con [Profesional]
                    del [Fecha] a las [Hora] ha sido cancelada
                    porque el profesional ya no está disponible."
           Tipo: advertencia

      - NO modifica citas ya pasadas (estado: realizada)
      - Log: Cantidad canceladas vs cantidad intacta

   5️⃣ ELIMINAR REGISTRO DE PROFESIONAL
      - findByIdAndDelete(profesional._id)

   6️⃣ ELIMINAR USUARIO
      - Ya se eliminó al inicio (findByIdAndDelete)

   ═══════════════════════════════════════════════════════════
   SI EL USUARIO ES CLIENTE:
   ═══════════════════════════════════════════════════════════

   1️⃣ BUSCAR SUS CITAS FUTURAS
      - Busca citas con estado: 'pendiente' o 'confirmada'
      - Solo las que sean futuras (fecha >= hoy)
      - Hace populate de: profesional, servicio, centro

   2️⃣ CANCELAR CITAS Y NOTIFICAR
      - Para cada cita futura:

        a) Guardar datos históricos (si no existen):
           • usuarioNombre (del cliente)
           • usuarioEmail (del cliente)
           • profesionalNombre
           • profesionalApellidos
           • servicioNombre
           • centroNombre

        b) Cambiar estado a 'cancelada'

        c) Enviar notificación al PROFESIONAL:
           Título: "Cita cancelada"
           Mensaje: "La cita de [Cliente] para [Servicio]
                    del [Fecha] a las [Hora] ha sido cancelada
                    porque el cliente eliminó su cuenta."
           Tipo: advertencia

        d) Enviar notificación a TODOS LOS ADMIN:
           Título: "Cita cancelada por eliminación de cliente"
           Mensaje: "La cita de [Cliente] para [Servicio]
                    del [Fecha] a las [Hora] ha sido cancelada
                    porque el cliente eliminó su cuenta."
           Tipo: info

      - NO modifica citas ya pasadas
      - Log: Cantidad canceladas vs cantidad intacta

   3️⃣ ELIMINAR USUARIO
      - findByIdAndDelete(usuarioId)

   ═══════════════════════════════════════════════════════════

   ⚠️ COMPORTAMIENTO CRÍTICO:

   ✅ LAS CITAS NUNCA SE ELIMINAN
      - Solo cambian de estado a "cancelada"
      - Permanecen en la base de datos
      - Visibles para auditoría e historial

   ✅ NOMBRES HISTÓRICOS PRESERVADOS
      - Se guardan ANTES de cancelar
      - Cliente: nombre + email
      - Profesional: nombre + apellidos
      - Servicio: nombre
      - Centro: nombre
      - Frontend NUNCA ve "null" o "Desconocido"

   ✅ CITAS PASADAS INTACTAS
      - Si fecha < hoy → No se modifica
      - Si estado = "realizada" → No se modifica
      - Mantiene historial completo

   ✅ NOTIFICACIONES AUTOMÁTICAS
      - Se envían a TODOS los afectados
      - Mensajes personalizados con detalles
      - Tipo apropiado (advertencia/info)

   ═══════════════════════════════════════════════════════════

   📊 EJEMPLO VISUAL:

   ANTES DE ELIMINAR CLIENTE "María López":
   ─────────────────────────────────────────────────────────

   Vista del PROFESIONAL:
   - Ve "María López" (NO "Desconocido")

   Vista del ADMIN:

   💡 VENTAJAS DEL SISTEMA:

⚙️ FUNCIONAMIENTO AUTOMÁTICO:

1️⃣ AL CREAR UNA CITA (POST /api/citas):
   ────────────────────────────────────────────────────────────
   - El backend busca: usuario, profesional, servicio, centro
   - Extrae los nombres de cada uno
   - Guarda TODOS los campos históricos automáticamente
   - No requiere acción del frontend

   Ejemplo de cita creada:
   {
     usuario: ObjectId("64f7a8b..."),
     profesional: ObjectId("64f7a9c..."),
     servicio: ObjectId("64f7a9d..."),
     centro: ObjectId("64f7a9e..."),

     // Campos históricos guardados automáticamente:
     usuarioNombre: "María López",
     usuarioEmail: "maria@example.com",
     profesionalNombre: "Laura",
     profesionalApellidos: "Gómez Ruiz",
     servicioNombre: "Corte de Cabello",
     centroNombre: "Glamour Studio"
   }

2️⃣ AL ELIMINAR USUARIO/PROFESIONAL:
   ────────────────────────────────────────────────────────────
   - ANTES de cancelar las citas, verifica campos históricos
   - Si algún campo no existe, lo guarda en ese momento
   - Luego cambia estado a "cancelada"
   - La referencia (ObjectId) puede quedar "huérfana"
   - Pero los nombres históricos están guardados

3️⃣ AL OBTENER CITAS (GET endpoints):
   ────────────────────────────────────────────────────────────
   - Hace populate normal de todas las referencias
   - Ejecuta función helper: agregarNombresHistoricos()
   - Si alguna referencia es null (eliminada):
     • Crea objeto con los campos históricos
     • Lo asigna a la propiedad correspondiente
   - Frontend recibe objetos completos SIEMPRE

   Ejemplo:

   CITA EN BD (después de eliminar usuario):
   {
     usuario: ObjectId("64f7a8b..."), // No existe en BD
     usuarioNombre: "María López",
     usuarioEmail: "maria@example.com",
     profesional: { nombre: "Laura", apellidos: "Gómez" },
     ...
   }

   DESPUÉS DEL HELPER (lo que recibe el frontend):
   {
     usuario: {
       nombre: "María López",  // ← Creado del histórico
       email: "maria@example.com"  // ← Creado del histórico
     },
     profesional: { nombre: "Laura", apellidos: "Gómez" },
     ...
   }

🔍 FUNCIÓN HELPER: agregarNombresHistoricos()

Ubicación: controllers/cita.controller.js (líneas 9-44)

Propósito:
- Detectar cuando referencias son null
- Usar campos históricos para crear objetos
- Garantizar que frontend nunca ve null

Código (simplificado):
```javascript
function agregarNombresHistoricos(cita) {
  const citaObj = cita.toObject();

  // Si usuario es null, usar históricos
  if (!citaObj.usuario && citaObj.usuarioNombre) {
    citaObj.usuario = {
      nombre: citaObj.usuarioNombre,
      email: citaObj.usuarioEmail
    };
  }

  // Si profesional es null, usar históricos
  if (!citaObj.profesional && citaObj.profesionalNombre) {
    citaObj.profesional = {
      nombre: citaObj.profesionalNombre,
      apellidos: citaObj.profesionalApellidos
    };
  }

  // Similar para servicio y centro...

  return citaObj;
}
```

Usada en:
- getAllCitas()
- getCitasByUsuario()
- getCitasByProfesional()
- getCitaById()
